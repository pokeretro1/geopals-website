# geopals-website

The public site for **Geopals Trading Card Game** — www.geopals.com.au

Plain HTML, CSS and JavaScript. No build step, no dependencies, no framework.
Every file that ships is a file in this repo.

## Run it locally

Double-click `index.html`. That's genuinely it — the card database loads its
rows from `data/cards.js` via a `<script>` tag specifically so the site works
off disk, with no web server.

If you later switch a database to a Google Sheet (see below), browsers will
block those requests from `file://` and you'll need a local server:

```
python -m http.server 8000     # then open http://localhost:8000
```

## Layout

```
index.html              home — game info, videos, how to play
cards.html              the card database UI
data/cards.js           the card rows (generated by the command centre repo)
assets/js/data.js       loading layer — JSON, Google Sheets CSV, or in-page data
assets/js/db-browser.js the search/filter/grid engine, dataset-agnostic
assets/js/cards.js      config that points the engine at the card database
assets/css/main.css     all styling; the colours are CSS variables at the top
CNAME                   custom domain for GitHub Pages
```

## Adding another database

The browser engine doesn't know anything about cards. To add a second database:

1. Copy `cards.html` → `lore.html`, change the title and the last
   `<script>` to `assets/js/lore.js`.
2. Copy `assets/js/cards.js` → `assets/js/lore.js` and edit the config:
   which fields are searchable, which become filter dropdowns, what shows in
   the detail panel.
3. The rows are already published to `data/lore-building.js` as
   `window.GEOPALS_LORE = [...]` — 48 public rows, every one carrying a `type`
   of `character`, `location`, `artifact`, `event` or `chapter`. Make `type` a
   facet and one page covers the whole world bible.

Leave `facets` out of the config and the filter dropdowns are worked out from
the data automatically — useful while a schema is still changing.

## Where the data comes from

Each database declares a `source` in its config file. Three kinds:

| Source | Use it when |
|---|---|
| `{ kind: 'global', name: 'GEOPALS_CARDS' }` | Rows live in `data/*.js`. Default. Fast, works offline, versioned in git. |
| `{ kind: 'json', url: 'data/cards.json' }` | Same idea, fetched at runtime. Needs a web server. |
| `{ kind: 'csv', url: '…/pub?output=csv' }` | Rows live in a published Google Sheet and you want edits live without a deploy. |

Switching between them is a one-line change. No UI code moves.

## Card artwork

Art is in Google Drive. A Drive **share link won't render** in an `<img>` tag,
so `data.js` extracts the file id and requests it from
`lh3.googleusercontent.com/d/<id>=w400`, which also serves a resized copy so
the grid isn't downloading full-resolution art.

Either the raw file id or a full share URL works in the `driveFileId` field.
The file must be shared as **Anyone with the link → Viewer**.

⚠️ **Drive is fine to launch on, but it isn't a CDN.** It rate-limits, sets no
useful cache headers, and Google has changed these URLs before. Once the card
list is stable, move the art into `assets/cards/` in this repo (free, fast,
versioned) or onto a real image host. The only thing that changes is how
`imageUrl()` builds the URL.

## Deployment

GitHub Pages serves this repo directly.

1. Repo → **Settings** → **Pages** → Source: `main`, folder `/ (root)`.
2. Custom domain: `www.geopals.com.au` (already in `CNAME`).
3. At your domain registrar, add a `CNAME` record:
   `www` → `pokeretro1.github.io`
4. Tick **Enforce HTTPS** once the certificate is issued (a few minutes).

Every push to `main` republishes the site.
